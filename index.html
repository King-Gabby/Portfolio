01
API-First Architecture
I structure AI systems around a clean API boundary. The model is a service, which is not an embedded function. This means FastAPI routes that accept structured input, validate with Pydantic, and return typed JSON; decoupling the model from the consumer and making the system testable.
02
Inference at the Right Layer
For real-time vision tasks (like ANPR or hand tracking), inference runs in a tight loop close to the capture source. For batch or user-triggered AI (like Bookiee AI), inference lives in /predict endpoints with response caching where the input is stable.
03
Deployment Mindset
I build with the target environment in mind: cold start time on Render, memory limits for free tiers, CORS headers, env-based config. I've debugged production failures over just watchin' them happen in localhost. That shapes how I structure code from the start.
04
Scaling Considerations
Even at early scale, I think about: stateless API design (easy horizontal scaling), model loading once at startup (not per request), and separating long-running inference from the request thread. When I add Docker and cloud later, the architecture is already shaped for it.
